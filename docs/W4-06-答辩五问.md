# W4-06 · 答辩五问准备

> 台账验收口径：编排在哪 · 调度策略是什么 · Self-Loop 改了哪一处 · 怎么验证 · 和 Dify 差在哪。
> 每题 40 秒答完，每问必须落到一个**具体界面或 trace 字段**，不靠形容词。

---

## Q1 编排在哪？

**答（指编排屏 DAG + core/graph.py）：**
"编排不是写死在函数里，是一张外置的图定义：节点 = {id, agent, deps, retry, timeout}，在 core/graph.py 里声明，core/orchestrate.py 按拓扑排序执行，每个节点进出各写一条 trace。验收方式是'换一份图定义，流程跟着变，执行器零改动'——界面上就是右屏这张 DAG，节点和连线全部由图定义驱动，前端代码不用动。行业切换（W4-04）就是换整套图定义：sales 换 service，角色、工具、流程图整体更换。"

**落点：** 编排屏 DAG 区；core/graph.py 节点定义；trace 的 step 行（agent / retry / status 字段）。

## Q2 调度策略是什么？

**答（指编排屏队列区）：**
"优先级队列：priority 数字大的先做，同优先级按提交顺序稳定排序，不随线程调度漂移；每个任务带 deadline，从它真正开跑那刻算起——排队时间不计入，因为槽位只有一个的批次里，把等待算进 deadline 会冤枉后面的任务。到点判 timeout，立刻释放槽位，后面的任务不用陪它等；被丢弃的结果在 trace 里标记 timeout。默认 deadline 外置在 config/scheduler.json，改配置即生效。同时提交高低优先两个任务，trace 时间线上顺序可证。"

**落点：** 编排屏任务队列区；config/scheduler.json 的 default_deadline_ms；trace 时间线。

## Q3 Self-Loop 改了哪一处？

**答（指诊断事件与两轮 prompt diff）：**
"核心一处：失败归因从'问模型'改成'确定性规则归类'。模型对自己的失败归因极不可靠——它总说'我表达不够清晰'，实际是根本没取数。所以 core/diagnose.py 用确定性规则把失败分成四类：无数据、取数错、口径错、表达错，每类给不同的修正策略：取数错重取，口径错退回上一步核口径，表达错只改表达、一个数字都不许动。重试上限 2 次，超限转人工兜底。trace 里每轮有一条 event=diagnosis 的记录，含 kind 分类和 signals 信号——两次失败分类不同，两轮 prompt 的 diff 可证。"

**落点：** 节点详情抽屉里的 diagnosis 事件；trace 的 kind / signals / attempt 字段。

## Q4 怎么验证？

**答（指回归报告 + verifier）：**
"三层。第一层数字回查：core/verifier.py 用正则抽回答里的数字，与本次工具返回的数值集合比对，对不上就带着'哪几个数没出处'打回重答——trace 里有 verdict 字段。第二层固定用例集：evals/cases.yaml 11 题，3 道故意易错（口径歧义、无数据、跨渠道），判定方式分 exact 精确值、must_contain 必须包含、must_refuse 必须拒答。第三层一键回归：python -m evals.run 一条命令出报告——通过率、平均耗时、平均 token、失败清单；恢复后首次回归 11/11 通过率 100%，报告 JSON 存档在 evals/reports/，同一版本连跑波动不超过 10%。失败题自动回流 regression 分组，下次必测。"

**落点：** evals/reports/latest.json；trace 的 verdict 字段；大屏 KPI 与 AI 回答逐位一致。

## Q5 和 Dify 差在哪？

**答（指 data_source.py 唯一入口 + budget/trace 字段）：**
"Dify 是通用低代码平台，强在拖拽拼装、接入生态广。我们做的是领域内嵌的确定性内核，差异在四件 Dify 不替你兜底的事：一，口径唯一——大屏和 AI 共用 data_source.py 一个数据入口，数字逐位一致，这是当场刷新页面也露不了馅的硬保证；二，验证闭环——verifier 数字回查加固定用例回归，回答的每个数字必须有出处；三，失败治理——确定性诊断分类而非模型自归因，降级必须写 trace 的 fallback 字段，不许悄悄换模型；四，成本可控——token 与调用次数上限外置在 config，触顶即中止并写 aborted=budget，已有结论照常交付。一句话：Dify 帮你把流程搭出来，我们把'搭出来的流程错的时候，你能不能知道'这个问题解决了。"

**落点：** trace 的 fallback / aborted 字段；config/team.json 的 budget 段；编排屏通道状态区。

### 备用追问（不在五问内，准备好一句话版本）

- **为什么三角色而不是一个 prompt？** Critic 的输入里不含 Analyst 的原始 prompt——只看工具返回的数和结论，避免顺着模型的说法走；trace 里三条 agent 记录可证。
- **断点续跑怎么做的？** 每节点完成即持久化 Blackboard 快照，失败后从最后一个成功节点继续，前序节点不重跑、不重复计费（core/graph.py + runs 快照）。
- **预算触顶什么表现？** run 停在超限处，返回已有结论并附「因预算上限中止」，trace 的 run_end 记 aborted=budget，回归可筛。
